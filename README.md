# 大水槽 — バーチャル水族館 🐟

ブラウザで動くリアル志向の水族館シミュレーション。外部アセットを一切使わず、
水の光学現象・生物の形・泳ぎ方・行動のすべてをコードで手続き生成しています。

## 起動方法

```bash
npm install
npm run dev      # 開発サーバ (http://localhost:5173)
npm run build    # dist/ にビルド
npm run preview  # ビルド結果の確認
```

| 🐬 イルカプール | 縁に囲まれた浅く明るいラグーン。白い砂底に3種13頭のイルカが暮らし、ときどき水面を突き破ってジャンプする |
| 🔦 深海 | 太陽の届かない漸深層。見えるのはダイバーライトが当たったものと、自分で光るものだけ |
| 🧊 流氷の海 | 南極の縁、海氷に蓋をされた大陸棚。光が入るのは割れ目(リード)からだけ。4種27羽のペンギンが群れごとに氷の下を飛ぶように泳ぎ、そろって息継ぎに上がり、板の上へ跳び乗る |

## 水と光のこだわり

### 水中

- **スネルの窓** — 水中から見上げると臨界角48.6°の円錐内にだけ空が見える現象。
  波で乱れた法線に対して屈折ベクトルを実計算し、窓の外は全反射の暗い鏡面になる
- **コースティクス** — 反復歪みによる集光模様。太陽方向へ投影した座標で評価するため、
  深い場所ほど模様が横へずれ、砂・岩・魚の体表すべてで光芒と整合する
- **光芒(ゴッドレイ)** — 水面から差し込む光条。動くノイズ + カメラ追従ビルボード
- **水中フォグ** — 距離による散乱に加え、視線の仰角で色が変わる(上は明るく下は深青)。
  散乱に使うのは**視線のうち水中を通った長さだけ**なので、水上から覗き込んでも破綻しない
- **深度減光** — 深いほど太陽光が届かない吸収表現を全マテリアルで共有
- **マリンスノー / 気泡** — 泡は上昇に伴い膨張(水圧)し、揺らぎながら水面で消える。
  位置計算はすべてGPU
- **前方散乱によるぼけ** — 水中では物から目へ向かう光が道中で細かく散らされ、
  **遠いものほど輪郭がぼやける**。シーンを一度テクスチャへ描き、深度から距離を
  復元して距離に応じた半径でぼかす(`src/postfx.js`)。
  **ただし効かせる範囲がすべて**で、ここは一度失敗しています(→ 下記)。
  水上へ出たら効果は切る——目と空のあいだに水がないので、
  同じ距離でも遠景は硬いまま見えるのが正しい

### 水面をまたぐ

カメラは水面を抜けられます。同じ一枚の水面を、視点が水の内か外かで別の物理で描き分けています。

- **空** — レイリー散乱の実測係数比から、視線の経路長に応じた散乱量を求める。
  天頂は青だけが散って深い青、地平線は経路が長く全波長が飽和して白く霞む。
  ミー散乱の前方ローブで太陽まわりのハロも出る。
  **この同じ関数をスネルの窓にも使う**ので、潜っても浮かんでも空の色が食い違わない
- **水上から見た水面** — フレネル反射(F0 = 0.02)で空を映す。水中の光路は視線が寝るほど
  1/sinθ で伸びるので、真下は中が透けて、水平近くはまったく見えなくなる
- **水面をまたぐ生き物** — 水上に出た体は空の環境光と直射日光で照らされ、
  背から集光模様が抜けていく
- **環境音** — 頭が水面から出ると、こもった低音から水面のさざめきへ入れ替わる

### 深海(照明モデルの反転)

深海ゾーンでは、これまで積み上げた光の表現がまるごと使えなくなります。
スネルの窓もコースティクスも光芒も、光源が水面にあることを前提にしているからです。
そこで**太陽の色をほぼ黒(`#020507`)にする**という一手で、太陽を掛けたすべての項を
同時に消しています。分岐を足すのではなく、入力を変えて既存の式を無効化する形にしたので、
浅い海のコードはそのまま残ります。

代わりに光源はダイバーライト1つになります。

- **スポットライトの円錐** — 視線に追従する。光錐の内と外で世界が完全に分かれる
- **赤の往復吸収** — 光は「ライト→対象→目」と水中を2度通ります。減衰係数は
  RGBで大きく違う(赤 0.042 / 緑 0.012 / 青 0.006 per m)ので、
  `exp(-vec3(0.042,0.012,0.006) * 距離 * 2.0)` を掛けています。
  結果、**赤いものは近づかないと赤く見えない**。
  遠くのAtollaクラゲは闇に溶け、寄って初めて血の色になります
  (深海生物が赤いのは、そこでは赤が「見えない色」だからです)
- **マリンスノー** — 光錐に入った粒だけが光る。闇の中を舞う雪がライトに浮かび上がる
- **自分で光るもの** — 発光は照明計算の外側で足します(`fishAlbedo` が `out vec3 emit` を返し、
  ライティング後・フォグ前に加算)。ライトを消しても光り続けるのが発光生物の条件です
- **環境音** — 泡の音が消え(水深1000mでは気泡が水圧で潰れます)、
  ローパスがさらに下がって、熱水噴出孔の低いうなりだけが時折届く

### 流氷の海(明るさを決めるのが深さではなくなる)

大水槽でもイルカプールでも、明るさは深さで決まっていました。太陽は水面ぜんたいから
均等に差してくるという前提です。氷の海ではこれが崩れます。海面の大半が板で塞がれ、
光が入るのは割れ目(リード)からだけ。**頭上に氷があるかどうか**が、深さより
はるかに強く効きます。

被覆率をXZ平面のテクスチャに焼いておき、`glsl.js` の `iceOpen()` として配りました。
`uIceOn = 0` のゾーンでは常に 1 を返すので、ほかの3ゾーンは1行も変わりません。

```glsl
// 太陽が傾いているぶん、影は水平にずれる
vec2 uv = (wp.xz + uSunDir.xz / max(uSunDir.y, 0.25) * depth) / uIceExtent + 0.5;
float cover = texture2D(uIceTex, uv).r;
float soft  = clamp(depth / 13.0, 0.0, 1.0);   // 深いほど影の縁は甘くなる
return 1.0 - cover * mix(0.95, 0.78, soft);
```

**太陽の項にだけ掛けても、影は出てきません。** 最初はそう書いて、氷の下と
割れ目の下がまったく同じ明るさになりました。氷が遮るのは直射日光だけではないからです。

- 直射日光(`sunReach`)
- 上向きの環境光 — 空から降ってくる光なので、これも氷が止める
- **水の色そのもの** — 水の色は「水中で散乱した日射」です。散らす光が届いていない
  のに水だけ明るいと、影の中の遠景だけが浮いて嘘になります

この3つ全部に同じ係数を掛けて、はじめて氷の下が暗くなります。
海底に落ちる明暗のモザイクが、そのまま頭上の板の並びです。

### 流氷そのもの

最初は円板をぶつからないように撒きました。できたのは流氷ではなく蓮の葉です。
海を覆う氷はもともと一枚で、それが割れてできたものだから、隣り合う板の輪郭は
**噛み合っていなければならない**。あいだにあるのは「板と板の隙間」ではなく
「板を割った線」です。

いまはボロノイ分割で作っています。ジッタ格子に種を撒き、各セルを板の輪郭にして、
全体を少しだけ内側へ縮める。縮めたぶんがそのまま割れ目の幅になります。

- **下面の厚み** — 頂点に「そこが何m厚いか」を持たせ、その厚みで透過光を
  減衰させています(`exp(-kappa * thick)`、赤から先に吸われる)。白く塗るだけでは
  発泡スチロールにしかなりません。厚い中央は青く沈み、薄い縁とひび割れだけが
  光を通すので、板ではなく**光る天井**に見えます
- **下面の形** — 中央がふくらんだレンズ形にすると、どう塗っても錠剤になります。
  ほぼ平らな板に、氷どうしが押し合ってできた竜骨(キール)と、波に削られた凹凸を刻む
- **開水面(ポリニヤ)** — セルを一枚ずつ間引いても開けた水面にはなりません。
  細い割れ目が少し増えるだけで、氷の下がどこも同じ明るさのまま。
  まとまった範囲ごと抜いて、光の落ちる場所をはっきり作る必要がありました
- **上面の雪** — 極地の雪は積もるだけでなく風に削られて硬い畝(サスツルギ)になります。
  卓越風の向きへ伸ばしたノイズで法線を傾け、窪みは空の青だけで照らされて青く沈む

### ぼかしすぎると「深い水」ではなく「濁った水」になる

最初は全域に効かせて、20mの魚まで溶かしていました。結果は「奥行きのある水」
ではなく「濁った水」です。水族館の大水槽は澄んでいて、20m先の魚は普通に
くっきり見えます。輪郭が崩れ始めるのは、フォグでもう色が抜けかけている
ずっと奥から。

いまは**光学的な深さ**(距離 × 濁り)で効かせる範囲を切っています。

```glsl
float tau  = distance * uDensity;        // 光学的な深さ
float soft = smoothstep(0.45, 2.2, tau); // 大水槽なら19m以内はまったく手を出さない
```

同じ式で、濁った深海(`uFogDensity` が大きい)では近い距離から効き始めます。
最大でも2.2px(1080p換算)。**近〜中距離にわずかでも手を出すと濁って見える**
というのが、ここでの唯一の教訓でした。

### 散乱のぼけを「集める」向き

ぼけは1画素の計算では作れないので、周囲から集める(gather)形で書きます。
ここで一度間違えました。

光を散らすのは**出てきた点**であって、見ている点ではありません。だから
「サンプルごとに、そのサンプル自身の距離で重みを決める」ほうが向きとしては
正しい。ところがそう書くと、探す範囲(遠い背景の広い半径)と実際に効く範囲
(手前の物の狭い半径)が桁で食い違い、12点ではまったく足りずに、
輪郭のまわりの輝度が `18→28→18→67→18→74` と振動しました。

中心画素の半径で素直に重み付けすると、点の密度が半径に見合うので滑らかに出ます
(`18→28→60→86→141→152→…`)。手前の物の輪郭が外側へわずかに滲みますが、
これは水中で実際に見える「もやの暈(かさ)」そのものなので、むしろ都合がよい。

検証は輝度の並びを直接読んで行いました。深度の復元(6m の板 → 6.27、
60m の板 → 59.61)、輪郭が振動していないこと、遠い板のほうが**自分の面の上で**
鮮鋭さを失っていること(頭打ちまで 1px 対 3px)、ポストパスを通しても色が
変わらないこと(18 対 18)を確かめています。

## 生物のこだわり(生態と遊泳様式)

### 大水槽

| 生物 | 実装した生態・動き |
|---|---|
| ジンベエザメ | 世界最大の魚類。**尾を左右にゆっくり振る**大型魚の遊泳。上下に平たい角の取れた頭、体側を走る3本の隆起、鎌形の胸びれ、5対の巨大な鰓裂。淡い縦帯と横線が作る格子の升目ごとに白斑が入る**市松模様**(個体識別に使われる)を手続き生成 |
| ザトウクジラ | 哺乳類なので**フリューク(水平の尾びれ)を上下に**振る——魚とは直交する遊泳軸をシェーダで切替。体長1/3の長い胸びれ。**息継ぎサイクル**で水面へ上がり泡を吹き、環境音ON時は鳴き声も合成。頭は平たい吻(ロストラム)で、弓なりの口の線と、その縁に並ぶ瘤(→ 下記) |
| マイワシ ×180 | ボイド群泳(分離・整列・結集 + 近傍認知上限)。クリックで**フラッシュ・エクスパンション**(爆発的散開)。エイ・カメを回避。銀鱗の虹色反射 |
| ナンヨウハギ | 体を曲げず胸びれで漕ぐ **labriform遊泳**。パレット模様・黄色い尾 |
| カクレクマノミ | イソギンチャクから離れない定住行動。腰を振る泳ぎ。黒縁の白帯3本 |
| マダラトビエイ | 翼端ほど位相が遅れる**羽ばたき滑空**。背面は白斑。腹面には口・鼻孔・5対の鰓裂が並ぶ(エイの腹面はこの造作が主役) |
| アオウミガメ | 前肢の**水中飛翔**。数十秒〜数分おきに**水面へ息継ぎに上がる**行動サイクル。甲羅は椎甲板5枚・肋甲板4対・縁甲板12対を実際の配列どおりに置き、**同じ配置から模様と溝の両方**を作る(→ 下記) |
| ミズクラゲ | **拍動遊泳** — 収縮は速く弛緩は遅い非対称波形で、収縮の瞬間だけ推進。四つ葉の生殖腺。口腕は慣性で遅れてなびく。傘の縁は寒天質が薄く尖って消えるので、**最外周でアルファを溶かす**(断ち切ると輪郭が白い硬い線になる) |
| チンアナゴ | 砂から上体を出してプランクトンを待ち、エイ・カメ・カメラが近づくと**瞬時に砂へ退避**。引っ込みは速く、出てくるのは恐る恐る |

### イルカプール

3種は体形・遊泳・跳躍の癖・鳴き声をそれぞれ別に定義しています(`DOLPHIN_KINDS`)。

| 生物 | 実装した生態・動き |
|---|---|
| バンドウイルカ ×4 | 全長3.7m。標準的な体形と鎌形の背びれ。口笛のようなホイッスル |
| シロイルカ ×3 | 全長5.0m で最大。丸く張り出した**メロン(額)**と、その後ろの**首のくびれ**(鯨類では珍しく頸椎が癒合していない)。流氷の下を泳ぐため**背びれを持たず**、代わりに後半身の正中線をこぶ状の稜が走る。幅広い櫂のような胸びれ。ゆったり泳ぎ、跳躍はまれで低い。「海のカナリア」らしく低く長く鳴く |
| カマイルカ ×6 | 全長2.5m で最小・最俊敏。**大きく反り返った鎌形の背びれ**(前後で色が分かれる)、黒い背と白い腹の間を走る淡灰色のサスペンダー模様。跳躍が断然多く、鳴き声は高く短い |

**寸法** — 全長(吻先〜尾びれの切れ込み)だけでなく、胴の太さも実測比に合わせています。
バンドウイルカとカマイルカの体高は全長の 0.17〜0.19 しかありません。ここを太くすると、
長さが同じでも「ずんぐり短い」シルエットになります。
逆にシロイルカはハクジラでも屈指の胴回りで、**最大胴周が全長の 0.81**(実物は 0.70〜0.85、
飼育個体は 0.80 前後)。ここを細くすると、いくら額を丸くしても筋肉質に見えません。

**シロイルカの体型** — 3種のなかで唯一、楕円断面の紡錘形では足りません。
「太った水滴」にしないために、4つを足しています。

- **メロンと首** — 額が独立した山になり、その後ろが少しくびれる。
  16点のプロファイルを線形で引くと制御点ごとに傾きが折れ、額の丸みが
  そのまま稜線として面に出るので、この種だけ Catmull-Rom で引いています
  (`smooth: true`)
- **背の稜** — 背びれの代わり。断面変形(`sectionMod`)で正中線を持ち上げ、
  こぶ状に波打たせています。シェーダ側の影の帯も同じ範囲に合わせること
- **尾柄のキール** — 尾の手前で断面が横へ張り出し、平たい板になる
- **櫂型の胸びれ** — 既定の胸びれは付け根の弦長が0で、根元が一点に集まった
  針のような形になります。細い翼ならそれでいいのですが、板状のひれには
  使えないので `shape: 'paddle'` を足しました

**ブリーチング** — 助走で潜ってから水面へ斜めに駆け上がり、離水後は弾道運動。

姿勢は速度ベクトルから作るので、**離水の瞬間に速度を作り直してはいけません**。
ここを踏み外すと必ず不自然な飛び出しになります。実際に2つ踏んでいました。

- 向きを中心向きに代入していた → 水面を割る1フレームで体が最大180度ねじれる
- 上昇を「水面までの残り距離」で駆動していた → 水面へ近づくほど上昇が緩んで
  水面直下ではほぼ水平になり、離水した瞬間に仰角が 0°→53° へ跳ねる

どちらも**助走のあいだに離水時の速度ベクトルへ寄せておく**ことで直しています。
水面に着いたときには、もう跳ぶ向き・跳ぶ角度・跳ぶ速さになっているので、
離水は状態を切り替えるだけで速度に一切触れません。

```
t(s)  状態     水面から  仰角     速さ
 0.42 charge    -6.29   41.3°   9.1     ← 助走のうちに仰角を立てる
 0.58 charge    -5.00   53.0°  10.8
 1.08 charge    -0.67   53.1°  10.8     ← 直前
 1.17 air        0.02   50.9°  10.3     ← 離水(重力ぶんしか変わらない)
 2.00 air        3.23   -1.4°   6.5     ← 頂点
```

着水点がプールからはみ出しそうなときは、向きではなく**前進の勢いだけ**を
助走中にじわじわ詰めます(`|pos + s·dir| = R` を解いて、収まる最大の
水平移動距離を求める)。速さは姿勢に出ないので、これは見えません。

離水と着水でしぶきが上がり、着水のほうがはるかに派手になる(落下のエネルギーが
一気に水面へ移るため)。着水後は白い泡の輪が水面のうねりに乗って広がりながら消えます。
水中からは水面に遮られて見えなくなるので、実際に水中から見上げたときと同じ
「消えて、戻ってくる」体験になります。

### ザトウクジラの頭

最初は寸法プロファイルの先頭が太いまま(体高の56%)で、そこから一点のキャップへ
一気に閉じていました。結果、鼻先が四角い円錐になります。直したのは3つです。

- **吻(ロストラム)を作る** — 頭は体長の3分の1。吻端はほとんど厚みのない板で、
  そこから背の線がほぼ直線に上がります。背の線と腹の線を先に決めて、
  そこから体高プロファイルと体軸オフセットを逆算しました
  (`hProfile = (背 − 腹)/2`、`yOffset = (背 + 腹)/2`)。
  腹側のほうが速く上がるので、体軸は前ほど高くなります
- **断面を平たくする** — 楕円断面のままだと、どれだけ細く絞っても丸い筒の先を
  削っただけの形にしかなりません。頭部でだけ背側の断面を超楕円(指数 < 1)へ寄せ、
  角丸の矩形に近づけています(`sectionMod`)
- **口の線を引く** — 背と腹の色の境目を、頭では口の線そのものにしました。
  吻端から下へ弓なりに垂れ、口角で上がるこの一本の弧が「ザトウクジラの顔」を決めます。
  縁には瘤(tubercle)が並びます。実物は直径5cmほどなので、
  粒の間隔と大きさは実寸に合わせ、上半分を明るく下半分を暗くして
  盛り上がりだけを感じさせています

### 体軸の上下——「ザトウ」の由来そのもの

吻を作ったあとも、まだイルカの体型でした。背が吻から尾まで一枚の滑らかな
ドームを描いていたからです。原因は**体軸オフセットの符号**でした。

側面図から背と腹の輪郭を10%刻みで読み取り、`(背−腹)/2` と `(背+腹)/2` に
分解して比べたところ、体高プロファイルはほぼ合っていて、体軸だけが逆でした。

| 体長に対する位置 | 0.0(吻) | 0.3 | 0.5 | 0.7 | 0.9 |
|---|---|---|---|---|---|
| 実物の体軸 | **−0.35** | −0.19 | 0.00 | **+0.22** | +0.15 |
| 直す前 | **+0.15** | +0.03 | 0.00 | **+0.03** | +0.06 |

実物は、頭が胴の中心線よりずっと下にぶら下がり(低く平たい吻と、垂れた喉)、
背は吻から7割地点まで上がり続けて、そこが体でいちばん高くなります。
——「座頭鯨」「humpback」の名の由来そのものです。
ここを逆(吻で高く)にすると、背が滑らかなドームになり、尖った吻を持つ
イルカの体型になります。

寸法も同じ図から測り直しました。断面の最大体高は全長の 0.237、
外接箱の高さは 0.261(体軸が上下するので、外接箱では体の太さを測れません)。
実装はそれぞれ 0.236 / 0.261 です。

### 胸びれを「翼」ではなく「腕」にする

ひれはどれも、断面ごとに前縁と後縁の2点だけを置いた**厚みのない板**でした。
まっすぐな弦、尖った先端、平らな面 — これは飛行機の主翼の作り方で、
生き物の腕にはそのどれも当てはまりません。ザトウクジラの胸びれは立体として作り直しています。

- **翼型の断面** — NACA4桁系の厚み分布で、前縁が丸く厚く、後縁へ向かって薄くなる
- **丸い先端** — 弦を先端で0にせず、輪郭を丸く閉じる
- **前縁の瘤(tubercle)** — この種のひれをひと目で見分ける特徴。飾りではなく、
  失速を遅らせて小さな半径で旋回するための構造です。前縁だけを押し出し、
  弦長で吸収させて後縁は滑らかに保ちます(両方に効かせると輪郭全体が波打つ)。
  **前後だけでなく厚みも持たせる**のが要点で、押し出すだけだと面が平らなまま、
  輪郭は波打つのに表面はのっぺり光ります
- **垂れ下がり** — 張り出し量を基準に効かせる。後退量を基準にすると、
  後ろへほとんど寝ないこのひれではただの水平な棒になります
- 上面は体と同じくらい暗い灰色、下面だけが白。上下とも白いと水中で一枚の紙に見えます

寸法は数値で検証しています(全長16.5mに対して、最大体高0.204・最大体幅0.163・
胸びれ長0.290・尾びれ幅0.349 — いずれも実物の範囲内)。

### 魚体の生成

魚の体は楕円断面リングの手続き生成で、頂点シェーダで
「振幅が尾に向かって増大する進行波」(subcarangiform)を与えて泳がせています。
法線も波の傾きに追従するため、泳ぐたびに体側の光が流れます。

断面は円に限らず、単位円上の点を変形する関数(`sectionMod`)を渡せます。
ジンベエザメの平たい頭や体側の隆起はこれで作っています。
模様の座標には注意が要り、体軸UVは吻の先端で一点に収束して潰れるため、
頭部の細かい斑点だけはモデル座標の3Dセルで散らしています。

### 甲羅の生成

アオウミガメの甲羅(`src/creatures/turtle.js`)は、平面形・甲板配置・断面を
実物に合わせて作り直しています。潰した卵形のドームでは生き物に見えません。

- **輪郭** — 前縁の左右に前肢を出すための切れ込みがあり、最大幅は中央よりやや前。
  後縁は縁甲板の継ぎ目ごとに内へ食い込んで波打つ(スカラップ)。
  原点から見て星形なので、角度→半径の表に落として引いています
- **甲板** — 椎甲板5枚・肋甲板4対・項甲板1枚・縁甲板12対をボロノイで分割。
  **この同じ配置から模様と溝の両方を作る**ので、絵と凹凸が必ず一致します。
  角質は成長中心(肋甲板なら外後方の角)から同心円状に足されるので、
  琥珀色の成長条はそこから放射させ、角度を歪ませて条の幅を不揃いにしています
- **断面** — 縁は水平に張り出すのではなく下へ巻き込み、そこから斜め内下へ
  絞って腹甲へつながる。垂直な壁にすると樽に入っているように見えます
- 甲板の溝は縁で効きを 0 に落とし、背甲と腹甲の縁がぴったり合うようにしています

テクスチャは数十万画素ぶんの計算になるため、格子ハッシュは `Math.sin` ではなく
整数演算、甲板検索は空間グリッド、低周波のノイズは半解像度で焼いてから参照、
としています(素直に書くと生成に1秒近くかかる)。

頭も同じで、比率を外すと生き物に見えません。眼から吻先までは頭幅の半分ほどしかなく、
頬は首よりはっきり太い。ここを逆にすると、頭のない細長い管になります。
首・頭・嘴は1本のロフトですが、モザイク鱗の粒は首と頭で変え(実物も頭頂は大きな板状)、
嘴だけは別マテリアルにしています。先端で断面が一点に畳まれるため、
巻きつけたUVは必ず潰れて星形や縞のノイズになるからです
(そもそも嘴は鱗ではなく滑らかな角質なので、模様を貼らないのが正しい)。
なお筒に巻くUVの繰り返し数は必ず整数にすること。一周して u が元に戻らないと、
頭の正中線にテクスチャの継ぎ目がまっすぐ走ります。

**誘引の実装** — `School` に `lure()`(誘引点へ向かう力)を足しました。
1フレーム限りで、置く側が毎フレーム呼び直します。警戒中の個体には効きません
(逃げている魚は光に見とれない)。
「光っているのに寄ってこない」のか「寄っているが襲わない」のかは画面写真では
区別がつかないので、実クラスを3分回して数えて調整しました
(エスカ1m以内の平均: 誘引あり 12.98匹 / なし 0.33匹、捕食動作12回)。

**口の作り方** — この魚でいちばん大事なのは口です。最初、断面の腹側を角度で
削って口にしたところ、歯が腹の縁に沿って並んだ「腹に裂け目のある別の生き物」に
なりました。作り直したものは順序が逆で、

1. まず**口線**を高さの関数として決める。口角(顎の蝶番)は頭のうしろ・体高の
   いちばん低いところ、そこから前上がりに走り、吻端では体の中心より上に出る
2. 断面のどこで上顎と下顎が分かれるかを、その口線から**逆算**する
   (`acos((体軸のy − 口線のy) / 体高)`)
3. 歯はその線に沿って並べ、上顎の歯は下へ、下顎の歯は上へ、
   どちらもわずかに喉の側へ倒して生やす

こうすると口角から吻端まで一本の線が通り、開閉しても牙が噛み合います。
吻端では上顎と下顎を一点に収束させること(ここを開いたままにすると、
正面から見たとき頭の前が筒のように空いて口の中が丸見えになります)。

**大きさ** — チョウチンアンコウを置いた瞬間に、ハダカイワシが42cmで
作られていたことが目に見えて分かりました。実寸(11cm)へ直し、遊泳速度・認知半径・
追跡距離もこの体長に合わせ直しています。並べてはじめて分かる嘘があります。

### ペンギンをペンギンに見せるもの

**体型は体重から出す。** これを目分量でやると必ず細長くなり、小型の鯨になります
(2回そうなりました)。体積 = π・H・W・胴長・断面の平均率、から H と W を逆算します。

ところが**体重から出しても痩せます**。そこで3回つまずきました。
どれも「式は合っているのに細い」という形で出てくるので、見た目の違和感から
原因にたどり着けません。

| つまずき | 中身 |
|---|---|
| 断面の平均率 | 「だいたい0.5」と目分量で置いていた。表から積分すると **0.64**。1割以上のずれ |
| 割る密度 | 肉の密度(0.9)を使っていた。描いているのは**羽毛の輪郭**で、抱えた空気のぶん見かけはもっと軽い。0.68 まで下げ、さらに後述の理由で **0.55** にした |
| 全長 | `total` は尾羽の張り出しを含まないのに、図鑑の「全長」をそのまま入れていた。どの種も1割長すぎて、同じ体重でもそのぶん痩せる |

**太さは目でなく胴回りで見ます。** 断面を楕円とみなして周長を出し、実測と比べます。

| | 胴回り |
|---|---|
| 見かけ密度 0.68 のとき | 74cm |
| **いま(0.55)** | **81cm** |
| 実物のオウサマペンギン | 75〜85cm |

0.68 でもまだ実測の下限を割っていました。効いているのは羽毛の空気層で、
ペンギンの羽は2〜3cmの厚さの空気を抱えています。半径11cmの胴に2.5cm足せば
13.5cm——線寸で23%、体積なら5割増えます。描いているのはこの外側の輪郭なので、
そのぶん見かけ密度は肉よりずっと下がります。陸では断熱のためさらに羽毛を立てます。

**細く見えた原因の半分は、太さではなく配りかたでした。** 腹のいちばん深いところが
前寄りだったので、立たせると胸から下がすぼまって、洋梨ではなく雫の形になって
いました。立ち姿では体軸が上下方向になるため、腹の最深部は「思っているより後ろ」に
置く必要があります。

そのうえで**輪郭を洋梨にします**。立たせると見えるのは頭より下——胸から腹に
かけての部分だけなので、そこが早く細ると一気に痩せて見えます。
紡錘形ではなく、腹を後ろまで太いまま保った洋梨だと思ったほうが近い。
頭は太らせません。体が太るほど頭は相対的に小さく見えるもので、
それがずんぐりした鳥の見え方そのものです。

そのうえで、**横から見た形**が3つの条件を満たす必要がありました。
体型はザトウクジラと同じく、背と腹の輪郭を先に決めて
`太さ = (背−腹)/2`、`体軸 = (背+腹)/2` に分解しています。

- **背の線は項から尾の手前までほとんど平ら。** 魚のように弓なりに盛り上げた瞬間、
  寸法が合っていても鯨になります。ペンギンの厚みは全部**腹側**に付いています
- **尻は丸い。** 尾柄を絞ると後ろ半分がそのまま魚です。ペンギンの尾は
  「丸い尻から突き出た小さな楔」で、胴のほうは最後まで厚みを保ったまま終わります
- **首のくびれは、横から見た項の窪みより「上から見た細さ」のほうが効きます**

**翼**はザトウクジラの胸びれ(`shape: 'flipper'`)を土台に、瘤をなくし、
平面形を付け根最大の一様テーパーへ差し替えました(弦長分布を表で渡せるようにしてあります)。
鯨類の胸びれのように中ほどが膨らむ分布のままだと、櫂ではなく飛行機の主翼になります。

### 羽毛の表面 — 描き込むほど嘘になる

「イルカと違って羽毛に覆われているはずなのに、ツルツルの肌に見える」という指摘を
受けました。**半分は当たっていて、半分は逆**です。

ペンギンの羽毛は鳥類でいちばん密で(1cm²あたり10〜15本)、短く硬く、瓦のように
重なって水を通さない一枚の面を作っています。だから3m離れると本当にウェットスーツの
ように見える。**羽毛をはっきり描き込むと、かえって嘘になります。**

それでもゴム人形に見えていた原因は3つあって、どれも「羽毛の描き込み不足」では
ありませんでした。

1. **粗さが色にしか入っていなかった。** 法線がなめらかなままだと、光の当たり方が
   磨いた面のそれになります。羽毛は色ではなく**陰影**で分かる表面なので、
   ここを揺らさないと質感が出ません。いまは羽の重なり(千鳥に並んだ瓦)で
   法線を倒しています。ただし遠くではちらつくので、**5m以内でだけ**出します
2. **濡れと乾きの区別が無かった。** 上がったばかりの個体は水膜で黒々と光り、
   乾いた個体はマットで明るい。羽毛は水を弾き、上がった個体は身震いして水を切るので、
   30秒ほどでほぼ乾きます
3. **白い腹には羽の構造を明示的に描いていなかった。** 消すと腹だけが塩化ビニルになります。
   いまは背より振幅を半分にして残しています

濡れ具合はインスタンス属性 `aWet` で渡します。最初は乾くのに90秒かけていましたが、
ペンギンが氷の上にいるのは7〜20秒しかないので、**乾く前に海へ戻ってしまって変化が
一度も見えませんでした**。同じ板の上に濡れた個体と乾いた個体が混ざるのが、
実際のコロニーの見え方です。

### 1羽ずつ違う

同じ種の27羽が同じ顔・同じ背格好で同じ動きをしていると、増やすほど
**気味が悪くなります**。群れに見えず、一個の生き物が複製されているように見える。

そこで見た目と気性の両方に個体差を持たせました。同じ `InstancedMesh` を
共有しているので、見た目のばらつきはインスタンス属性 `aTrait` でシェーダへ渡します。
既定値 `(0,0,0,1)` がそのまま「標準の個体」になるよう置いてあるので、
属性を渡さないほかの魚には一切影響しません。

**見た目**

| | |
|---|---|
| 太り具合 | 胴だけに掛けます。脚に掛けると足裏の位置が変わって立ち姿の接地計算が崩れ、翼に掛けると個体ごとに翼長が変わります。太った鳥の足と翼は大きくなりません |
| 首の長さ | 頭と嘴をまとめて前後へ。嘴を置いていくと顔から外れます |
| 顔の模様 | 種ごとに変える場所が違う(下記) |
| 羽色 | 換羽が近い個体は日に灼けて褐色に褪せます。大多数は艶のある黒で、褪せた個体は少数 |

顔は種によって「個体差が出る場所」が違います。**ジェンツーの眉斑**は個体識別に
使えるほど差が大きく、頭頂でしっかりつながる個体から、細く途切れる個体までいます。
**キングの頬斑**は太さと、喉へどこまで垂れるか。**ヒゲの顎紐**は太さ——名前の由来
そのものなので、ここが全員同じだと4種のうちで最も双子に見えます。
**アデリー**は白い眼輪の太さと、頭巾が首のどこまで下りるか。

**気性** — せっかちさ・好奇心・落ち着きのなさ・よちよちの深さを1羽ずつ持たせました。
せっかちな個体は歩調が速く、立っていられる時間が短い。好奇心の強い個体は
潜水者に寄ってきて長く付いてまわり、臆病な個体はその場に留まります
(全員がいっせいに寄ってくると、群れではなく一個の生き物に見えます)。

分布は一様乱数ではなく、一様乱数を2つ足した三角分布です。一様だと全員が
「そこそこ違う」になって、かえって平均的な群れになります。実際は大多数が標準で、
たまに際立った個体がいる。

歩調を変えるときは**速さも同じ率で変えること**。片方だけいじると
「歩幅 = 速さ × 接地時間」が崩れて足が地面を滑ります。

### 「これ、鳥に見えない」

ここまでで形は合っていたのに、それでもまだ鳥に見えませんでした。
足りなかったものは3つあって、どれも欠けると一目で嘘だと分かります。

**1. 裸の脚。** 鳥の脚は途中で羽毛が切れて、鱗に覆われた裸の部分が出ます。
見えているのはいちばん先の一節——跗蹠(ふしょ)と3本の前趾、そして爪だけで、
大腿も脛も羽毛の下に折り畳まれています。**この一節があるかないかが、鳥か海獣かを分けます。**
前は足を「尾の下から生えた蹼の板」として作っていました。それだと足首が体の
なかほどにあることになり、尻のほうが下まで垂れて足が宙に浮きます。
跗蹠は体のいちばん後ろの下端(体長の95%)まで届いていなければなりません。

足首は**球関節**として作ります。跗蹠の先を足首を中心とした半球で閉じ、
足の踵をその球のなかから始めれば、いくら回しても継ぎ目が開きません。
足そのものは薄い膜を1枚張るのではなく閉じた薄い立体にして、趾の骨の通る
3本のところだけ背側に厚みを盛ります(`aHeight` で跗蹠と足を区別し、
シェーダは足首から先だけを回します)。

**2. 尾の関節。** これは下の「足が地面に届かない」で書きます。

**3. 羽毛の質感。** ペンギンの羽は小さく硬く、瓦のように重なって体を覆っています。
面をなめらかに塗ったままだと、どれだけ形を合わせてもゴムの人形に見えます。
高い周波数の粗さと羽の列を入れるだけで、同じ形が鳥の皮膚に寄ります。

### 翼を打つ鳥の泳ぎ

魚もイルカも体をくねらせて連続的に進みますが、ペンギンは翼を打つ鳥なので、
数回強く打って加速し(バースト)、翼を伸ばしたまま滑る(グライド)を繰り返します。
速度計を付ければ鋸波になります。

**ここを一定速度にすると、翼をどれだけ正しく動かしても推進しているように見えません。**
最初はバーストとグライドの速度差が1.19倍しかなく、ただ翼が動いているだけの物体でした
(いまは1.50倍)。

羽ばたきの位相は**時間×周波数では作れません**。打つ速さが刻々変わるので、
速さを変えた瞬間に位相が飛んで翼が瞬間移動します。CPU側で積分し、
振幅とあわせてインスタンス属性で渡しています。振幅0が「翼を左右に伸ばした滑空姿勢」です。

**気泡**は吐いた息ではありません。羽毛のあいだに抱えこんだ空気が、加速と水圧で
押し出されているもの。だから速く泳いだときと深いところでだけ出ます。
粒は生まれた時刻・場所・初速だけをCPUが書き、あとの運動はGPUが解きます。

**常に泳いでいるわけではない。** バーストとグライドを繰り返すだけだと、
何かに追われているように延々と走り続けます。ペンギンは水中で立ち止まって
あたりを見回している時間がかなりあるので、滑りに入るときに種ごとの確率で
そのまま**ホバリング**へ移ります。翼は前進のときとは別の動き——小刻みに速く、
振幅は小さく——になり、首を少し上げて見回し、気泡も出しません。

**翼の付け根で脇腹が破れる** — 翼の内端は体に埋まっています。そこまで一様に回すと、
振り上げた瞬間に埋まっていた部分が脇腹を突き破り、体側に幅3画素の白い線が現れました
(部位IDを色分けしたデバッグ描画で正体が分かりました)。付け根付近の回転を殺して解決しています。
肩の皮膚が翼に付いていかないのは生き物でも同じです。

### 4種の habits を分ける

同じ体型・同じ泳ぎ方にしておくと、模様が違うだけの4種になります。
遊泳層・群れの密度・旋回の鋭さ・立ち止まりやすさを種ごとに変えました。

| | 遊泳層 | 群れ | 旋回 | 立ち止まり | 弧の本数 | 氷へ上がる |
|---|---|---|---|---|---|---|
| オウサマ | 深い(海底寄り) | ばらける | 鈍い | 多い | 1〜2 | 16% |
| ジェンツー | 浅い | ふつう | **鋭い** | 少ない | **4〜8** | 30% |
| アデリー | 浅い | **密** | ふつう | ふつう | 3〜6 | **42%** |
| ヒゲ | 中 | ふつう | 鋭い | **多い** | 3〜5 | 36% |

キングは深海性で海底近くを長く泳ぎ、息継ぎも静かに浮上して終わります。
ジェンツーは最速なので浅い層を鋭く曲がり、息継ぎは連続したポーポイジングで済ませます。
アデリーはひとかたまりで動き、氷の上にいる時間がいちばん長い。
ヒゲは水中で立ち止まっている時間が長い。
——同じ水槽を4種が別々の高さ・別々のリズムで使っている状態になります。

### 息継ぎ・ポーポイジング・氷への飛び乗り

氷の海では**どこで浮上するか**が決定的です。板の下でいくら浮上しても息はできません。
### 群れで動く

最初は個体ごとに勝手な深さで泳ぎ、勝手な時刻に息継ぎへ行っていました。
結果は水槽じゅうに散らばった点の集まりで、**どこを見ればいいのか
分からない**絵になります。囲いの外へ出たら中心へ戻す、という力しか
かけていなかったので、囲いのなかを銘々にうろつく雲にしかなりません。

ペンギンは群れで海に出ます。餌場へは隊列で泳ぎ、潜水も浮上もそろえ、
氷に上がるときも一緒に上がります。だから**群れの重心をひとつ置いて、
そこを泳がせる**ことにしました。個体はそれに寄り、向きをそろえます。

| 何を群れで決めるか | 効果 |
|---|---|
| 息継ぎの行き先 | 全員で同じ割れ目へ向かう。個体ごとに選ばせると同じ群れが四方へ散る |
| 潜水のタイミング | 群れ全体が一斉に消えて一斉に出てくる |
| 上陸する板 | 同じ板の上へ、少しずつ位置をずらして降りる。氷の上に固まりができる |
| 泳ぐ深さ | 銘々の深さで泳がせると上から下までまんべんなく散って、層が見えない |

重心は実際の群れの位置へゆるく引き戻します。これが無いと、上陸などで
足並みが乱れたとき重心だけが先へ行って、誰もいない場所を目指して
全員が追いかけることになります。

**先陣を切りたがらない。** 氷の縁でペンギンが溜まってなかなか飛び込まないのは、
いちばん最初に入るのがいちばん危ないから(ヒョウアザラシが待っています)。
逆に一羽が入ると堰を切ったように続きます。一羽が縁へ歩き出したら、
残りの休憩時間を数秒に縮めてあります。

まとまり具合は数で見ます。いまは群れの半径が4.7〜7.6m、上下の広がりが
0.6〜1.6m、そして**同じ行動をしている個体の割合が78〜98%**です。
キングだけ広いのは、この種が深く潜ってばらけて泳ぐからで、そう作ってあります。

潜水時間を使い切ったペンギンは、開水面か氷の縁を探して向かいます。

- **ポーポイジング** — 水面すれすれを走りながら低く長い弧を繰り返す。
  これは息継ぎのついでの跳躍ではなく、速く泳ぐための手段です。水面ぎわを泳ぐと
  造波抵抗で急に重くなるので、ある速さを超えると空中を飛んだほうが安く済みます
- **氷への飛び乗り** — 板の乾舷を越える必要があるので、こちらは立ち上がりが急になります。
  まず板を越える高さを満たす初速を出し、その滞空時間で着地点まで届くかを見る。
  届かないなら、水平を速くするのではなく**もっと高く跳ぶ**(滞空時間を伸ばす)。
  水平だけ上げると板をかすめて向こうへ飛び越します
- **上陸後** — 着地の勢いで少し腹這いに滑り、そこから**立ち上がります**。
  氷の上に立ち、ゆっくり向きを変えながらあたりを見て、時間が来ると
  **よちよちと縁まで歩き**、ブリンクで**体を前へ倒して頭から飛び込みます**(→ 下記)

板を突き抜けないよう、氷の下面と甲板は格子へ焼いてあります(`bakeField`)。
板146枚ぶんの atan2 とノイズを毎フレーム回すわけにはいかないためです。

息継ぎ地点と上陸点は、**カメラが届く範囲**(半径34m)に絞ってあります。
流氷は160m四方に敷いてありますが、カメラは半径42mまでしか出られないので、
絞らないと「たどり着けない板の上でペンギンが立っている」ことになります。

### 首を曲げられるようにする

最初は氷の上でも腹這いのままにしていました。理由は「この体は首が曲がらない
一本の紡錘形なので、直立させると嘴が真上を向く」から。しかしこれは順序が逆で、
**曲がらないなら曲げられるようにすればいい**。

頂点シェーダに首の関節を1つ入れました。頭と嘴だけを、首の付け根を軸に回します。

- **軸は項(うなじ)寄りに置く** — 体の中心に置くと、曲げたとき喉がつぶれて
  背が伸びます。実際の頸椎は背側を通っています
- **配分は胴の3割を使う** — 短い区間で切り替えると、首が一点で折れて鉤になります。
  実際の首は何個もの椎骨がすこしずつ曲がってS字を描きます
- **嘴は曲げをまるごと受ける** — 頭蓋に固定されているので、胴と同じ配分にすると
  頭だけ倒れて嘴が置いていかれます

同じ仕組みで**翼を体側へ畳めるように**しました。ここも一度失敗していて、
肩を軸に後ろへ回すだけだと翼が正中線へ寄って胴の中に沈み、消えてしまいます。
畳んだぶんだけ外へ逃がして脇腹に沿わせる必要があります。

立ち姿の高さも、目分量の式で出すと必ず氷に埋まるか浮きます(次項)。

### 立てる形にする

最初の立ち姿は、体を75度に起こしただけのものでした。結果は前へつんのめった
ボウリングのピンです。足りなかったものが2つありました。

- **傾き** — ペンギンの脚は体のうしろに付いていて、**尾を地面につけて三点で支える**ので、
  体はまっすぐ立つか、わずかに後ろへ反ります。75度では重心が足より前に出ます。
  いまは86度
- **足** — 泳ぎ用に尾のうしろへ畳んだままでした。体の真下に細い棒が刺さって
  いるだけで、どう見ても自立していません。足首(`uFootPivot`)を軸に
  **90度前へ倒して**、足裏を地面に向けた板にします。
  実物の足はキングで13cmあり、これが体を支える面になります
- **翼は畳みきらない** — ぴたりと体側へ貼りつけると、脇腹と同じ黒が重なって
  輪郭に溶け、翼がどこにあるのか分からなくなります。実際のペンギンも
  立っているときは翼をわずかに開いています

**脚の寸法は胴の太さに連動させます。** 最初、足の大きさも左右の間隔も
「体長の何倍」で書いていました。胴を太くしたときにここが取り残されて、
幅広の体を細い2本で支える絵になります。

脚は腹から生えているので、**左右の間隔は体長ではなく腹の広さで決まります**
(いまは胴の半幅の0.26倍)。胴が太くなれば付け根も外へ出るのが道理です。
ただし外へ出しすぎると、そこの腹の面が丸みで持ち上がるぶん脚が早く羽毛から
出て、鷺のような長い脚になります。

| | いま | 実物のキング |
|---|---|---|
| 足の長さ | 13.5cm | 13〜15cm |
| 3趾の張り出し | 9.5cm | 8〜10cm |
| 両足の中心間 | 6.3cm | — |

支えが広くなったぶん歩きも安定して、接地中の足のずれは歩幅の3.9%から
**3.0%**に下がりました。

脚の付け根も尾の先から腹の後ろへ移しました。
ペンギンの脚が体のかなり後ろにあり、大部分が体に隠れていることが、
そのまま次の「歩幅が取れない」話につながります。

### 足が地面に届かない — 尾の関節と、接地の実測

それでもまだ立っていませんでした。**尾が折れていないので、足が地面に届かない。**

体をほぼ垂直に起こすと、胴の後ろ半分から尾の先までが全部「真下」になります。
いちばん下に来るのは尾の先で、そこが甲板に触れる高さまで体を持ち上げると、
足首は体のなかほどの高さに残り、足が宙にぶら下がります。

首と同じで、曲がらないなら曲げられるようにすればいい。尾骨の付け根
(`uTailPivot`)を軸に尾を**後ろへ蹴り出す**関節を足しました。曲げは尻の
あたりから徐々に配分します——一点で折ると総排出腔のあたりに折り目が立って、
尾を差し込んだように見えます。曲げた尾はそのまま三点目の支えになります。

そして**接地の高さは式で書かず、ジオメトリから解きます。**
二度書いて二度とも外れました(一度目は尾が刺さり、二度目は足が浮いた)。
`solveStand()` が頂点シェーダとまったく同じ変形をCPUで掛けて、

- `standDrop` — 体の原点から足裏までの深さ。甲板からの浮かせ量そのもの
- `standBend` — 足裏より下に残るものが無くなるまで尾を曲げた角度
- `standHalfW` / `standFwd` — 接地点の左右の広がりと、体の真下からの前へのずれ

を実測します。尾の長さは種で倍以上違う(ジェンツーはキングの2倍)ので、
曲げ角を定数にはできません。

探索に**曲げても動かないもの(嘴と跗蹠)を混ぜてはいけません。** 踵は足裏の
すぐ上にあるので、混ぜると「いくら尾を曲げても余裕が出ない」ことになって
探索が上限まで走り、尾が背中へ跳ね上がります(実際そうなりました)。

接地しているかどうかも目で見ずに測ります。`test_footing.mjs` が同じ変形を
掛けて足裏の世界座標を出し、そこへ真上から光線を落として氷のメッシュと
比べます。差が浮きか埋まりそのもので、いまは4種とも±2cm以内です。

**このとき氷の側の嘘も見つかりました。** 甲板の高さ場は雪の起伏を落として
平均だけを焼いていたのに、描いているメッシュのほうは吹き溜まりで20〜30cm
うねっていました。だから「立っているのに膝から下が氷に埋まっている」絵に
なっていて、原因が生き物側にあるとしか見えませんでした。
いまは高さ場もメッシュも `deckAt()` という1本の式から出しています。
さらに、氷の無い升目を `-1e4` で埋めた配列をそのまま線形補間していたので、
板の縁の1升手前で甲板が水面下まで引きずり降ろされていました。
甲板だけは、氷のある升目だけで重みを取り直しています。

### よちよち歩き — 「揺らす」では歩きにならない

一度目は「位置を等速で足して、体を左右に揺らす」で作りました。
結果は氷の上を**滑りながら体を振っている**だけ。揺れの大きさをどう直しても
直りません。**足が地面を掴んでいないのだから当然**でした。

作り直したものは、脚の位相を主役にして、そこから全部を出します。

**1. 接地している足は動かない。動くのは体のほう。**
あたりまえに聞こえますが、これを守ると寸法が全部つながって決まります。

| 決まるもの | 出どころ |
|---|---|
| 歩幅 | 2・R・sin θ (R=脚を振る軸から足裏まで、θ=振り出しの片振幅26度) |
| 歩調 | 脚を振り子とみた固有周期の1.6倍。ヒトも鳥もだいたいこの比 |
| 速さ | 歩幅 ÷ (接地時間の割合 × 周期) |

ジェンツーで R=14.7cm、歩幅13.5cm、周期0.48秒、速さ0.42m/s。
**速さを先に決めて足を後から付けると、どうやっても滑ります。**
接地中の角度は時間に対して一次で回します(厳密には asin ですが、
差は1mmに収まる)。

**2. 左右の倒し込みは「揺れ」ではなく、遊脚を地面から離すための動作。**
脚が短く足が大きいので、支持脚の上へ体を倒さないと反対の足が上がりません。
Griffin と Kram は、この倒し込みで力学的エネルギーの8割を回収していることを
示しました。よちよち歩きは無駄な動きではなく、歩くための仕掛けそのものです。

倒すとき、**回転の中心は体の真ん中ではなく接地した足**です。
高さだけ直して横を放っておくと、倒し込むたびに支持足が6cm横滑りします。
体のほうを足の上へ送らなければなりません。重心は直進せず、
左右に数センチずつジグザグに振れながら進みます。

**3. 荷重の配分から作る。** 「浮いていないほうの脚が支えている」で
切り替えると、踏み替えの1フレームで体が左右に跳びます。歩行には両脚が
同時に着いている時間があり、そのあいだに荷重が片方からもう片方へ移ります。
倒し込みも、体を足の上へ送る量も、この配分から出します。

**4. 体をひねる。** 脚が正中線の近くに付いているので、片脚を前へ出すと
骨盤ごと回ります。この回旋がないと歩幅が取れません。

**5. 上下動は勝手に出る。** 支持脚が垂直になる一歩の中間で体はいちばん
高く、踏み替えでいちばん低い。倒立振り子そのもので、別に弾みを足す必要は
ありません。

**6. 遊脚は跗蹠を1割縮めて上げる。** 縮めないと、支持脚とすれ違う瞬間
——両脚とも垂直になるところ——で足が地面を擦ります。実際は膝が折れている
のですが、軸方向に縮めるだけで足りました。

そのために、左右の脚を別々の部位番号(6=左 7=右)にして、
シェーダが片脚ずつ「足首 → 跗蹠の縮み → 付け根」の順に回すようにしました。
順番を逆にすると足裏が地面に対して傾きます。

**測り方。** 滑って見えるかどうかを目で見ても分かりません。
`test_gait.mjs` が頂点シェーダと同じ変形をCPUで掛けて足の世界座標を毎フレーム
記録し、**接地しているあいだにその足が何mm動いたか**を測ります。
いまは一歩あたり歩幅の4〜5%(5〜9mm)です。

残っているずれの正体は**体のひねり**でした。左右の足は前後にずれた位置に着いて
いるので、体を鉛直軸まわりに回せば、どちらかの足は必ずその場でひねられます。
打ち消しようがない——実際の足も氷の上でそうやって捻れている——ので、
打ち消すかわりに振れ幅のほうを抑えてあります。
(倒し込みのほうは左右の足に同じだけ効くので、こちらは打ち消せます。)

この測定で最初に引っかかったのは、測り方のほうの間違いでした。
「足のいちばん低い頂点」を追うと、体が傾いたときに内側の趾と外側の趾で
拾う頂点が入れ替わり、その差(6cm)がそのまま「滑り」として出ます。
滑りを測るなら、同じ物質点をずっと見なければなりません。

**個体ごとの体格倍率(±8%)も掛け忘れてはいけません。** 立ち高さも歩幅も
歩調も伸び縮みします。掛け忘れると、大きい個体は氷に3cm埋まり、
小さい個体は浮きます。関節の軸(頂点シェーダの uniform)も同じで、
拡げ忘れると回すたびに脚や首が本来と違う場所へ動きます。

### 縁で倒れてから落ちる

立った姿勢からいきなり弾道へ渡すと、水面を割る1フレームで体が +75度 から
−30度 までねじれます。イルカのブリーチングで踏んだのとまったく同じ失敗です。

半歩先の足元を見て、そこに氷がなければ歩くのをやめ、0.75秒かけて体を前へ
倒しきってから離れます。**倒れる動作そのものが入水の初速**になります。
頭から入るので、しぶきは腹から落ちたときの半分ほどにしてあります。

**跳べない不具合を2つ踏みました。**

- 遊泳の天井を一律「水面まで」にしていたので、跳ぶための上向きの速度が作れず、
  いつまでも水面下をなぞっていました。頭上を塞いでいるのは氷だけで、水面は壁ではありません
- 助走の目標を水面ちょうどに置いていたので、近づくほど残り距離が0に収束して
  上昇がゆるみ、水平になってしまう(イルカのブリーチングとまったく同じ罠)。
  目標は水面より上に置きます

### 氷の原を「タイルの床」にしない

水上から見ると、同じ厚みの板が敷き詰められた床にしか見えませんでした。
原因は3つあって、どれも「氷が平ら」だからではなく「氷が一様」だからです。

**1. 厚みを一様にしていた。** 実際の海氷には、その冬に凍った一年氷
(薄くて平ら、水面とほとんど面一)と、夏を越した多年氷(融けきらずに
厚みを増し、表面が丘のようにうねる)が混じっています。いまは板ごとに
どちらかを引かせていて、厚みは 0.5m から 4.8m まで、水面上に出る高さで
10倍ほど違います。

**2. 氷丘脈(圧力リッジ)が無かった。** 板どうしが押し合うと、接した縁が
座屈して瓦礫の壁になります。上に1〜2mせり上がり、下にはその倍以上の
竜骨が垂れる。**流氷の原が「タイルの床」ではなく「地形」に見えるのは、
ほぼこれのおかげ**でした。押し合っている縁とそうでない縁があるので、
方位ごとに強さを持たせて、半分ほどの縁だけを立たせています。
瓦礫なので、滑らかな土手ではなく高周波のノイズで崩します。

ペンギンが上がる縁は、壁の立っていない方位から選びます。実物も
低い縁から上がります。

**3. 氷山が無かった。** 海氷とは出自がまったく違います。海氷は海面が
凍ったもの(塩水・薄い・平ら)、氷山は氷河や棚氷から割れて流れてきた
真水の氷の塊です。

| | 見え方 |
|---|---|
| 中身 | ブライン(塩水の管)が無いので透明で深く青い |
| 表面 | それでもほとんど白い。風化して表層が細かい気泡だらけになるから。**青が出るのは水に濡れた水際から下と、割れ目のなかだけ** |
| 年層 | 何万年ぶんの雪が押し固まった縞。**水平**に走る |
| 沈み方 | 大部分が水面下。ここの水深は15m前後しかないので、置いた氷山はどれも海底に座礁している |

全面を青くすると氷ではなく色ガラスの塊になり、年層に横方向のノイズを
強く混ぜると縞が縦に立ってバーコードになります(どちらも一度やりました)。

形は卓状(棚氷から割れたばかり)と尖峰状(融けて崩れて久しい)を混ぜます。
卓状ばかり並べると、箱を置いただけの絵になります。
水面下の本体は当たり判定に入れてあります——泳いでいて塊をすり抜けたら
台無しです。光芒も氷山の上には立てません(塊を突き抜ける光の柱になる)。

### 氷の海は凪いでいる

ほかのゾーンの水面は外洋のうねりで山と谷が2mほど動きます。同じものを
氷の海に出したら、**氷の上に立っているペンギンが波に飲まれました**。

測ってみると理由は明白で、流氷の板の乾舷(水面から甲板までの高さ)は
中央値でわずか32cm、下位25%では17cmしかありません。うねりの山は+1m。
半分以上の氷が波の下に沈む計算です。

海氷は波を吸います。固まった流氷の中では海面はほとんど平らで、だから
極地の探検家は氷の中の海を「millpond(ため池)」と書きました。そこで
うねりの振幅をゾーンごとの倍率にして、氷の海だけ **0.12倍**(±12cm)に
落としました。ごまかしではなく、これが本来の姿です。

あわせて、**上陸点にも乾舷を要求**するようにしました。薄い板は水面すれすれに
浮いていて、そこへ上げると「氷の上に立っているのに波に洗われている」絵に
なります(実際、うねりの山より低い上陸点が14%ありました)。18cm以上の
乾舷を条件にしたら候補は83→42カ所に減りましたが、27羽には充分で、
波を被る上陸点は0になりました。

### 磯の生き物 — 泳がないものたち

ここまでの4ゾーンの生き物は、全員が泳いでいました。姿勢は進行方向から決まり、
地面に触れることもない(ペンギンが氷に上がるときだけが例外)。

磯はまるごと逆で、住んでいるのはほとんどが**泳がない生き物**です。
共通して要るのは2つ。

- **岩の面に「乗る」こと。** 位置だけでなく傾きも岩に合わせます。水平に置くと、
  傾いた岩から浮いたり刺さったりします
- **潮を見ていること。** いま自分が水の中にいるのか外にいるのかで、できることが変わります

| | |
|---|---|
| **イソガニ**(甲幅3〜7cm) | 岩の上を脚で歩く。潮が満ちているあいだは活発、干上がると物陰で待つ。クリックすると岩陰へ走る |
| **ミドリイソギンチャク**(3.5〜7cm) | 水に浸かると触手を開き、空気にさらされると全部たたんで丸い塊になる |
| **イトマキヒトデ**(5〜9cm) | 岩に張り付く。腕の先だけがわずかに反る |
| **ムラサキウニ**(殻4〜7cm) | 岩の窪みに嵌まる。棘がゆっくり動く |

**カニが横に歩くのは、脚の関節が体の横方向にしか曲がらないから**です。前へ出そうと
すると隣の脚とぶつかる。だから先に行く側の脚が岩をつかんで体を引き寄せ、反対側が押す。
漕ぐような歩き方になります。

**作りこむ場所を間違えないこと。** ペンギンでは接地足の滑りを歩幅の3%まで詰めましたが、
4cmのカニを1m先から見るとき、脚先の数mmのずれは見えません。ここは正弦波の伸縮で足ります。

**26匹中25匹がその場で回り続けた**ことがありました。原因は「1歩ぶんの高低差」で崖かどうかを
判定していたこと。岩には節理の溝が数cm刻みで走っているので、1歩(数mm)で数cmの段を跨ぐことは
いくらでもあります。それを崖とみなしていました。カニは4cmの体で数cmの段を平気で越えるので、
見るべきは「これから進む先30cmの傾き」のほうでした。

**イソギンチャクは閉じるのが速く、開くのが遅い**(閉じ1.6 / 開き0.35)。乾けば死ぬので
閉じるのは一瞬でよいけれど、開くのは「もう安全か」の判断が要る。動かない生き物にとって、
警戒を解くのは高くつきます。

**磯の環境音** — ほかのゾーンの環境音は「途切れずに続くざわめき」ですが、
磯だけは形のある一発ずつの出来事です。寄せるときに低い唸りが近づき、砕けた瞬間に
高域が立ち、引くときは細かい音が残る。**帯域を時間で動かさないとシャワーの音**に
しかなりません。砕ける音には白色雑音が要ります——下地に使っているブラウンノイズは
高域がほとんど無いので、帯域を上へ振っても明るくなりません。

**環境音** — 氷の海でいちばん耳につくのは、板どうしが押し合ってきしむ音です。
帯域ノイズでは軋みに聞こえないので、音程が滑り落ちる細い音に、
細かいびびり(スティックスリップ)を混ぜています。
水中は蓋をされた空間なので、深海とは逆に高域がよく残って響きます。

## えさをまく

水族館でいちばん人が集まるのは餌の時間です。それは魚が動くからではなく、
**魚がこちらの行動に応えて動く**からだと思います。眺めるだけの水槽と、
一度でも餌をまいた水槽とでは、そのあとの見え方が変わります。

なので餌は「粒が舞うエフェクト」にはしませんでした。撒いた粒は世界に残って
漂い・沈み・やがて散り、生き物がそれを目指して寄り、**1粒ずつ食べて減っていきます**。
減っていくのが見えないと、食べているようには見えません。

### 餌はゾーンで違う

| ゾーン | 餌 | 起きること |
|---|---|---|
| 大水槽 | アミエビ(3.8cm) | イワシの群れが水槽の反対側からでも寄ってきて**ベイトボール**を作る。ジンベエザメが口を開けたまま通り、まとめて漉しとる |
| イルカプール | 生きた小魚(9.5cm) | 水面近くでひらめく。イルカが巡航をやめて直行し、食べたあと跳ねる |
| 深海 | 沈降する有機物(3.8cm) | まっすぐ沈む。ハダカイワシが群がり、底に積もったぶんはユメナマコが掃除する |
| 流氷の海 | 南極オキアミ(5.8cm) | 自分で泳ぎ、密な群れを作る。ペンギンが群れごと突っこみ、オキアミは跳ねて散り、また集まりなおす |
| 磯 | 砕いた貝や魚の身 | 岩の上に落ちて止まる。カニが匂いに気づいて集まり、はさみで拾う |

### 餌も生き物として作る

最初、餌は丸い点スプライトで描いていました。結果は「光っている何か」で、
まったくリアルに見えませんでした。理由ははっきりしていて、この水族館の
ほかのものはすべて**光を受けて陰のつくジオメトリ**なのに、餌だけが陰も遠近も
持たない発光する円だったからです。水のなかに浮いているのではなく、
画面に貼られていました。

なので餌もジオメトリで作り直しました。オキアミはエビだし、小魚は魚だし、
沈降物は不定形の塊で、どれも丸い光の玉ではありません
([`src/creatures/feedShapes.js`](src/creatures/feedShapes.js))。

- **エビ** — 頭胸甲より一段細い6節の腹部、腹側への反り、水平に開く尾扇、
  腹の下に並ぶ遊泳肢、そして体のわりに大きい真っ黒な複眼。
  なめらかな紡錘形にすると、たちまち小魚に見えてしまいます
- **小魚** — 側扁した体と二叉の尾。背が暗く腹が銀白で、水中の小魚は
  この明暗だけでそれと分かります
- **沈降物** — 正20面体を種にした小片を7つ、ゆるく寄せた房。
  マリンスノーは殻や糞や粘液が絡まった凝集体で、なめらかな石ではありません

描画はほかの生き物と同じ共有GLSL(半球環境光 + 太陽 + ダイバーライト + フォグ)
を通します。深海では**撒いた餌がライトの光錐に入ったときだけ**浮かび上がります。
向きは進行方向へ向け、頭を固定して尾へ向かうほど大きく振るしなりを頂点シェーダで
与えています。漂うだけの粒と泳いでいる生き物を分けるのは、この2つです。

### 大きさを実寸にしたら、今度は見えなくなった

点スプライトのころは実寸の倍ほどの大きさで描いていました。ジオメトリにして
実寸(オキアミ5.8cm)にすると、10m先ではほとんど見えません。**それが物理的には
正しい**のですが、餌をまいた手応えがなくなります。

大きさを盛って誤魔化すのではなく、**密度**で解きました。ナンキョクオキアミの群れは
動物の集団としては世界でいちばん密な部類(1立方メートルあたり1〜3万匹)なので、
粒を増やし(120→190)、群れの結集を強めて中心半径を縮め(0.8m→0.4m)、
撒く距離も手前に寄せました(6.5m→5.0m)。実物よりまだ100倍は疎いのですが、
橙色の雲としてはっきり見えます。

### 群れは「一匹ずつ誘われる」のでは寄ってこない

最初、餌のまわりに引力を置いて近くの個体を引き寄せていました。これだと群れが
10m以上離れていると**いつまでも気づきません**(実測: 餌から13m、しかも遠ざかる一方)。

実際のイワシが餌の時間に水槽の反対側から寄ってくるのは、一匹ずつが誘われるからではなく
**群れごと向きを変える**からです。そこで誘引とは別に、群れの回遊目標そのものを餌へ
置きかえる `feedAt()` を用意しました。これで最短距離が 13m → 2.4m になります。

ただしそれでも食べません。群れは餌の雲の**まわりを回るだけ**で、口が届かないからです
(最短でも粒まで2.4m)。原因は全個体が雲の中心という同じ一点を狙うことで、外側で
押しあうだけになるためでした。

そこで個体ごとに雲のなかの**別々の点**を狙わせ、そこに着いたら次の点を選びなおす形に
しました。あわせて、餌についているあいだは整列・結集を4割に弱めています。
プランクトン食の魚が餌の塊にたどりつくと、整った群れの形はいったん崩れて
めいめいが粒を追う——その状態です。これで最短距離が **2.4m → 0.15m** になり、
実際に減りはじめました。

### 食べる速さをフレームレートから切り離す

「口が届いた個体から1粒食べる」を素直に書くと、**速いPCほど餌が一瞬で消えます**。
毎フレーム1粒なら 60fps では毎秒60粒で、撒いた直後に消えてしまい、
餌に群がる場面そのものが見られません。

なので餌の雲は「1秒あたりの口数」(`rate`)を持ち、生き物側はそれを消費します。
溜めこめるのは2口までで、カクついたフレームのあとにまとめて消えることもありません。
プランクトンは毎秒7口なので、110粒がおよそ16秒かけて減っていきます。

### 数字

- 粒は最大300。位置はCPUで動かし、`InstancedMesh` の行列を毎フレーム書き換えて
  います。「食べたら消える」を素直に書くには、GPU任せにしないほうがよいためです
  (撒いているあいだの fps 低下は計測できませんでした)
- オキアミと小魚だけは自分で泳ぎます。捕食者が2.2m以内に来ると跳ねて散り
  (オキアミの逃避反応=テイルフリップは動物プランクトンでいちばん速い部類)、
  そのあと群れの中心へ戻ります。ペンギンに散らされ続けても
  半径2.5m前後で釣りあい、群れとして保たれます(実測)
- ボタンには2.6秒のクールダウンがあります。連打で水槽を埋めるとかえって
  何も見えなくなるためです

## 岩に「乗せる」ということ

磯の生き物は、はじめは岩に沈んでいました。歩くたびに地面へめり込み、
岩そのものも薄っぺらく見えていました。

原因は、**描いている岩と、その上に立たせる高さの出どころが別だった**ことです。

- 岩を描くとき: 190mを480分割した格子の頂点で `shoreTerrain()` を呼び、
  頂点のあいだは三角形で埋める
- 生き物を置くとき: `shoreTerrain()` を直に呼ぶ

`shoreTerrain()` は連続関数なので、幅4cmしかない節理の溝にもきちんと落ちます。
けれども頂点は7cm刻みなので、格子はその溝を持っていません。
生き物は「画面には無い窪み」の底に置かれていました。差は実測で **-22cm〜+12cm**。
甲幅3〜7cmのカニが、自分の体の3倍も埋まるか、12cm宙に浮くかのどちらかでした。

流氷でペンギンが氷にめり込んだときとまったく同じ構図で、教訓も同じです——
**描くものと、その上に立たせるものは、同じ高さの出どころを見ていなければならない。**

そこで「いま画面に描かれている岩の高さ」を返す `meshHeightAt(x, z)` を作り、
生き物・転石・餌・カメラのすべてをこちらへ移しました。

### 4隅を混ぜるだけでは足りなかった

最初は格子の4隅を双線形補間しました。ずれは22cmから3cmまで減りましたが、
消えませんでした。1マスは四角ではなく**三角2枚**で、対角線で折れているためです。
双線形はその折れを無視するので、四角の「捻れ」の半分ぶんずれます。
3cmは、甲幅3cmのカニ1匹ぶんです。

`PlaneGeometry` の分割は `(a,b,d)(b,c,d)`。マス内の位置 `tx + tz` で
どちらの三角かを選び、その3頂点が張る平面をそのまま読むようにしました。

結果、カニ26匹・イソギンチャク120・ヒトデ34・ウニ40の**220個体すべてで、
足元の高さとレイキャストした岩面の差が 0.0000m** になりました。

あわせて、カニの浮かせ量も測り直しました。甲羅の厚みから当て推量で
体長の16%としていましたが、いちばん低いのは甲羅ではなく歩脚の先(-0.17)で、
脚が岩に刺さったまま歩いていました。幾何の bounding box を measure して、
その値をそのまま使っています。手で置いた数字は必ずずれます。

## 遊泳層

大型生物は遊泳層を分けて共存させています。巨体どうしがすれ違いざまにめり込むのを防ぐためです。

| 生物 | 遊泳層(水面 y=16) |
|---|---|
| ジンベエザメ | y 3.4 〜 5.2(底層) |
| ザトウクジラ | y 9.9 〜 11.9(中〜上層)。息継ぎのときだけ 12.9 まで |

深海ゾーンではハダカイワシが y 5.0 以上、ユメナマコは海底から数十cm以内、
チョウチンアンコウは定位置(y 8.2)でほとんど動きません。

## 当たり判定

障害物を楕円体で近似した衝突ワールド(`src/collision.js`)を全生物とカメラで共有しています。

- **岩・イソギンチャク**は実体のある障害物。めり込んだら最短距離で押し出し、
  速度から面に食い込む成分を取り除いて表面を滑らせる
- **海藻**はしなるので「避けるが押し戻さない」やわらかい障害物として扱う
- **砂底**は高さ場としてクランプ。大型生物は進行方向の地形を先読みし、
  迫ってくる海底を余裕をもって越える
- **大型生物同士**も動く障害物として登録され、互いを避けて泳ぐ。
  細長い生物は楕円体を**体の向きに追従**させる(軸平行のままだと、泳ぐ向きによって
  前後がはみ出したり横が不必要に太くなったりして、めり込みとすり抜けの両方が起きる)
- 回避は接近速度に応じて強まるので、正面から突っ込むほど早く舵を切る

## PWA対応

ホーム画面に追加してアプリとして起動できます(スタンドアロン表示)。

- Service Worker は**ネットワーク優先**: 開き直すたびに必ず最新版を取りに行き、
  取得したものでキャッシュを更新する。古い画面が残り続けることはない
- オフライン時のみキャッシュにフォールバックし、圏外でも水槽が開ける
- タブ復帰のたびに SW の更新チェックを行い、新版が有効化されたら自動リロード
- ハッシュ付きビルド資産(`/assets/`)のみ不変としてキャッシュ優先(内容が変われば
  ファイル名が変わるため、常に最新性は保たれる)

### 圏外でどこまで動くか

生き物・地形・テクスチャ・音はすべて実行時生成なので、**一度オンラインで開けば
あとは通信ゼロで全機能が動きます**。実測(`dist` を配信 → 接続を全部切って操作):

| | 圏外 |
|---|---|
| 起動・描画 | ○ |
| ゾーン移動(大水槽 ⇄ イルカプール) | ○ |
| 図鑑・生き物の追跡 | ○ |
| 環境音 | ○ |
| 遊び方の動画 | 一度でも再生していれば ○ |

動画だけは実ファイル(mp4 4.3MB / webm 2.4MB)なので、**開いてもいないうちから
勝手に落としに行かない**方針にしています。一度再生すればキャッシュに入り、以後は
圏外でも見られます。`<video>` は Range リクエストで飛んできますが、206 Partial
Content は Cache API に保存できない(`cache.put` が例外を投げる)ため、SW 側で
「全体を一度だけ取ってキャッシュし、Range は自前で切り出して 206 を組み立てて返す」
処理を入れています(`sw.js` の `media()`)。

## 技術構成

- [Three.js](https://threejs.org/) + Vite。魚は `InstancedMesh` + カスタムGLSL
- ボイドは一様グリッドの近傍探索で O(n)、180匹 + αを60fpsで駆動
- ライティングは全カスタムシェーダで統一(半球環境光 + 太陽 + コースティクス + フォグ +
  ダイバーライト)。標準マテリアル(岩・カメ・煙突)には `onBeforeCompile` で注入。
  ゾーンごとの見え方の違いは分岐ではなく**ユニフォームの値**で表現しているので、
  深海を足しても浅い海のシェーダは1行も変わっていません
- しぶき・泡・マリンスノーは粒の位置・寿命をすべて頂点シェーダで計算(CPU負荷ゼロ)。
  発生源の位置と時刻だけをユニフォームで渡す
- 外部テクスチャ・モデル・音源ファイルなし。すべて実行時生成

```
src/
├── env.js                # 共有ユニフォーム・世界定数
├── glsl.js               # 共通GLSL(ノイズ/空/コースティクス/フォグ/ライティング)
├── noise.js              # CPU側ノイズ(地形・遊泳経路)
├── collision.js          # 楕円体ベースの衝突ワールド
├── camera.js             # ダイバー視点の自由カメラ(水面を抜けられる)
├── environment/          # 背景・水面・砂底・岩・海藻・光芒・泡・深海の地形
├── creatures/            # 魚体生成・遊泳シェーダ・ボイド・各生物
│   ├── feed.js           # 撒いた餌。漂い・沈み・食べられて減る
│   └── feedShapes.js     # 餌のかたち(エビ・小魚・沈降物)
├── zones/                # ゾーン定義(環境・生物・図鑑を1つにまとめる)
├── species.js            # 図鑑データ
├── ui.js / audio.js      # UI・環境音
└── main.js               # ゾーンの構築と切替・メインループ

media/                    # 遊び方の動画(ビルド時に dist/ へそのままコピー)
icons/ manifest.webmanifest sw.js 404.html   # PWA一式(同上)
```

ゾーンは初回訪問時に構築し、以降は表示の切り替えだけで往復します。
地形の高さ場は差し替え可能で、生物・当たり判定・カメラはすべて同じ関数を参照するため、
ゾーンごとに底の形が変わっても整合が保たれます。
